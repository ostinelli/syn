Treat documentation and code comments as timeless current-state guidance.
Never use changelog language such as "used to", "previously", "now", "no
longer", or "changed from", and never narrate an edit or compare the current
implementation with an earlier one. Git history is the place for change
history. Describe the current contract and explain its rationale when useful
(for example, "done this way so it doesn't break Z").

When committing, add yourself as a Co-author.
